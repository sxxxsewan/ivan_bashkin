# Исправления реализации

| Было | Стало |
|---|---|
| Пользовательского клиента не было. | Добавлен веб-клиент с авторизацией, фильтруемым постраничным списком, карточкой выдачи и сводкой; токен хранится только в памяти вкладки. |
| `benchmark.py` замерял только вход и список, не записывал CSV и не включал разложение времени. | Замеряются все шесть операций контракта, вычисляются p50/p95/максимум, размер параметров, SQL-время/число запросов; результаты дописываются в CSV с меткой набора. Прогрев исключен из расчета. |
| SQLAlchemy `echo=True` выводил SQL в лог вместо отдельного измерения. | SQL-логирование выключено; SQLAlchemy cursor events суммируют время и число запросов по каждому HTTP-запросу, значения передаются через заголовки измерения. |
| Карточка выдачи загружала связанные данные лениво при сериализации. | Читатель, экземпляр и книга загружаются связанным запросом при чтении карточки. |
| Входные даты выдачи без timezone могли сохраняться как naive datetime. | Naive `due_date`, переданный клиентом, интерпретируется как UTC. |
| Удаление строк при повторном seed не сбрасывало PostgreSQL sequence, поэтому идентификаторы менялись; время создания читателя бралось из DB default. | PostgreSQL очищается через `TRUNCATE ... RESTART IDENTITY`, SQLite sequence сбрасывается, `created_at` читателя зафиксирован, а валидный хеш seed-пользователя сохраняется; даты выдач вычисляются от одного момента запуска. |
| README не содержал полного контракта, клиентского адреса и условий испытания; пример ключа не соответствовал требованию `changeme`. | Документация приведена к фактическому контракту, добавлены шаги запуска, команды проверки/замеров, таблица окружения и незаполненные поля испытаний; `.env.example` использует только демонстрационные значения. |
| Правила штрафа уже считали полные дни между фактическим возвратом и сроком возврата с тарифом 100 за день. | Проверено по коду и оставлено без изменения; добавлены проверки просрочки, своевременного возврата и суммы штрафа. |

Проверка кода не выявила дефекта пагинации: запрос списка использует `LIMIT/OFFSET`, а `total` рассчитывается отдельным count-запросом с теми же фильтрами. Объемы `small` и `large`, фиксированный генератор случайных категорий и единая точка отсчета дат в `seed.py` уже соответствовали требованиям; они сохранены. Новые сущности, индексы, кеши, очереди и внешнее хранение файлов не добавлялись.

Тесты, миграции, API, benchmark и приложение не запускались по требованию; корректность изменений подтверждена только чтением кода.
